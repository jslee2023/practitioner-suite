Understanding URL & Percent-Encoding

Essential developer reference for RFC 3986, query strings, and Unicode serialization.

% What is Percent-Encoding?

Standard URLs may only be sent over the Internet using the standard 128 ASCII character-set. Since URLs frequently contain characters outside ASCII (such as Korean, Japanese, Cyrillic, or emojis) as well as reserved structural delimiters like ?, &, and #, they must be converted into a valid format using percent-encoding.

Percent-encoding replaces unsafe ASCII and multi-byte UTF-8 bytes with a % followed by two hexadecimal digits representing the byte value.

⇄ Component vs Full URL Mode

1. encodeURIComponent (Recommended for Params): Escapes all delimiters including &, =, /, and ?. Essential for query parameter values so they don't break the URL syntax.
2. encodeURI (For Complete Addresses): Preserves protocol and separator tokens (://, ?, &, /) while escaping illegal characters like spaces and Unicode glyphs.

Frequently Asked Questions

Why do some spaces encode as '+' and others as '%20'?

Standard RFC 3986 specifies %20 for spaces in path and query components. However, HTML form submissions (application/x-www-form-urlencoded) traditionally replace spaces with +. UtilinOne supports both modes and automatically decodes + into spaces.

Is my sensitive data (tokens, passwords, API keys) safe here?

Yes, 100%. UtilinOne is built with zero server-side components. All calculations and string manipulations take place in your browser's local JavaScript execution context. No network requests are made with your data.

How does UtilinOne handle malformed URLs or invalid percent-encodings?

If an invalid hexadecimal sequence like %ZZ or an incomplete percent sign at the end of a string is encountered, UtilinOne safely isolates the error, explains the cause, and avoids unhandled browser exceptions.
